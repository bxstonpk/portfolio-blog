## ภาพรวม

ระบบนี้ใช้ติดตามถังและไลน์ท่อในโรงงานน้ำมันปลาแบบเรียลไทม์ ตามสภาพโรงงานจริงคือมีภาชนะ 9 ใบ และเซนเซอร์ 14 จุด แบ่งเป็นเซนเซอร์ระดับของเหลว 5 จุด กับมิเตอร์วัดอัตราการไหล 9 จุด สิ่งที่ระบบทำได้ตอนนี้คือรับค่าจากเซนเซอร์ เก็บเป็นข้อมูลย้อนหลัง แสดงผลเป็นแดชบอร์ดและภาพ 3D และแจ้งเตือนเมื่อค่าเกินเกณฑ์

จุดเริ่มต้นของงานคือต้นแบบเดิมที่ backend ไม่มีฐานข้อมูล ไม่มีระบบล็อกอิน และข้อมูลทั้งหมดเป็นค่าสุ่ม ผมเขียน backend ใหม่ทั้งหมดด้วย Go แล้วปรับ frontend เดิม (React + TypeScript) ให้ใช้กับ API และระบบล็อกอินจริง

## สถาปัตยกรรม

```
อุปกรณ์ / simulator ──MQTT──► Mosquitto ──► mqtt-ingestor ──► InfluxDB (ค่าเซนเซอร์)
                                                 │
                                                 └──► PostgreSQL (alarm rules, alarm events)
                                                            │ LISTEN/NOTIFY
frontend (React) ◄──REST + WebSocket── api ◄────────────────┘
```

Backend เป็น Go ที่วางโครงแบบ hexagonal (ports & adapters) และแยกออกเป็น 3 ตัวที่ใช้แกนกลางร่วมกัน

- **api**: REST API สำหรับหน้าเว็บทั้งหมด รวมถึงล็อกอิน จัดการผู้ใช้ และตั้งค่า ตัวนี้ไม่ได้เชื่อมกับ MQTT เลย
- **mqtt-ingestor**: เป็นตัวเดียวที่รับข้อความ MQTT ทำหน้าที่เขียนค่าลง InfluxDB และตรวจเกณฑ์ alarm
- **simulator**: ใช้ตอนพัฒนาเท่านั้น ส่งข้อมูลจำลองผ่าน topic เดียวกับอุปกรณ์จริง พอต่ออุปกรณ์จริงแล้วก็ปิดตัวนี้ได้ ส่วนอื่นไม่ต้องแก้

ที่แยก api กับ ingestor ออกจากกัน ก็เพื่อไม่ให้ทั้งสองล้มตามกัน ถ้า MQTT มีข้อมูลเข้ามาเยอะหรือ broker รีสตาร์ต หน้าแดชบอร์ดยังใช้งานได้ตามปกติ

ฐานข้อมูลแบ่งหน้าที่กันชัดเจน **PostgreSQL** เก็บข้อมูลที่ผู้ดูแลแก้ไขได้ เช่น ผู้ใช้ รายการถัง รายการ tag เกณฑ์ alarm และใบสั่งงานซ่อม ส่วน **InfluxDB** เก็บเฉพาะค่าเซนเซอร์ตามเวลา ระบบนี้ไม่ใช้ Grafana เพราะ frontend วาดกราฟเองด้วย ECharts อยู่แล้ว

## การรับข้อมูลและแจ้งเตือน

เมื่อ ingestor ได้รับค่ามา 1 ค่า จะทำตามลำดับนี้

1. เขียนค่าลง InfluxDB ตาม timestamp ที่ส่งมา
2. อ่าน alarm rule ของ tag นั้นจาก PostgreSQL ทุกครั้ง แก้เกณฑ์ในหน้า Settings แล้วมีผลกับค่าถัดไปทันที
3. ถ้าค่าเกินเกณฑ์ จะบันทึก alarm event โดยมี cooldown 5 นาทีต่อ rule ต่อระดับ ค่าที่เกินต่อเนื่องจึงไม่ท่วมตาราง
4. ค่าที่เก่ากว่า 2 นาที (เช่น ข้อมูลค้างที่ gateway ส่งตามมาหลังเน็ตกลับมา) จะถูกบันทึกตามเวลาจริงของมัน แต่ไม่นำไปตรวจ alarm เพราะ alarm ควรบอกสภาพโรงงานตอนนี้

การแจ้งเตือนบนหน้าเว็บใช้ WebSocket ทำงานแบบนี้ ingestor กับ api เป็นคนละ process เมื่อ alarm เปลี่ยน ingestor จะส่งสัญญาณผ่าน PostgreSQL `LISTEN/NOTIFY` แล้ว api ส่งต่อให้ทุกหน้าจอที่เปิดอยู่ ข้อความที่ส่งเป็นแค่สัญญาณให้หน้าเว็บดึงข้อมูลใหม่ผ่าน REST ไม่ได้ส่งเนื้อหา alarm ไปด้วย ถ้า WebSocket หลุด หน้าเว็บจะกลับไป polling แบบช้า ส่วนข้อมูลเซนเซอร์บนแดชบอร์ดยังใช้ polling อยู่ (หน้า 3D ดึงใหม่ทุก 10 วินาที)

![หน้าการแจ้งเตือน: แยกระดับ Critical / Warning / Info และกดรับทราบได้](images/projects/tank-monitoring-iot/notifications.webp)

นอกจากรับค่าที่ map เป็น tag แล้ว ระบบยังรับข้อมูลดิบจาก gateway ได้ด้วย คือส่งมาแค่ address ของอุปกรณ์กับค่าแต่ละ channel แล้ว server จะ map อุปกรณ์ → channel → tag และแปลงสเกลให้เองตาม data map ในฐานข้อมูล ถ้าเพิ่มเซนเซอร์ใหม่ก็แค่เพิ่มแถวใน data map ไม่ต้องแก้โค้ด เมื่อเขียนค่าลง InfluxDB สำเร็จแล้ว server จะตอบ ack กลับไปที่ gateway

## Gateway หน้างาน

ฝั่งหน้างานผมเขียน flow ด้วย Node-RED ไว้รันบน industrial gateway ทำหน้าที่อ่านค่าจากโมดูล I/O ผ่าน Modbus TCP แล้วส่งขึ้น server ผ่าน MQTT มีระบบ store-and-forward สำหรับตอนเน็ตหลุด

- ถ้าเชื่อมต่ออยู่ จะส่งทันทีและพักข้อมูลไว้ในหน่วยความจำจนกว่าจะได้ ack (ไม่เขียนลงดิสก์ เพื่อถนอม eMMC/SD)
- ถ้าเชื่อมต่อไม่ได้ จะเขียนลงไฟล์ โดยเขียนไฟล์ชั่วคราวก่อนแล้ว rename จึงไม่มีไฟล์ที่เขียนค้างครึ่งทาง
- เมื่อต่อกลับได้ จะส่งข้อมูลที่ค้างเรียงจากเก่าไปใหม่ และลบไฟล์หลังได้ ack แล้วเท่านั้น

**สถานะตอนนี้:** flow นี้ทดสอบกับข้อมูลจำลองบนเครื่องพัฒนาเท่านั้น ยังไม่ได้ทดสอบกับ gateway และโมดูล I/O ตัวจริงหน้างาน

## ล็อกอินและสิทธิ์

- access token เป็น JWT อายุประมาณ 15 นาที
- refresh token อายุ 30 วัน เก็บในฐานข้อมูลแบบ hash และส่งเป็น httpOnly cookie ที่ JavaScript อ่านไม่ได้ ทุกครั้งที่ refresh จะออก token ใหม่ และ logout จะยกเลิก token จริง
- สิทธิ์มี 4 ระดับคือ `admin`, `engineer`, `operator` และ `viewer` endpoint ที่แก้ไขข้อมูลต้องเป็น admin ยกเว้นการอัปเดตใบสั่งงานที่ engineer ทำได้

## Deploy และ CI/CD

- รันทั้งระบบด้วย Docker Compose ได้แก่ PostgreSQL, InfluxDB, Mosquitto, api, mqtt-ingestor และ web (nginx) มี reverse proxy กับ Let's Encrypt แยกไว้อีกชุด
- CI บน GitHub Actions: backend รัน `go build`, `go vet` และ `go test` ส่วน frontend รัน lint และ build
- branch `dev`: หลัง CI ผ่าน จะสร้างระบบเต็มชุดบน runner ของ GitHub เอง ตรวจ health แล้วปิดทิ้ง
- branch `main`: หลัง CI ผ่าน จะ SSH เข้า server แล้ว deploy
- Simulator สร้างค่าแบบ deterministic จาก (tag, เวลา) จึงเติมข้อมูลย้อนหลัง 90 วันได้ต่อเนื่องกับข้อมูลสด ทำให้กราฟมีข้อมูลให้ดูตั้งแต่ติดตั้งครั้งแรก

## สิ่งที่ยังไม่ได้ทำ

- ยังไม่ได้ทดสอบ gateway กับอุปกรณ์จริงหน้างาน
- หน้า Reports ตอนนี้เป็นแค่รายการรายงาน ยังสร้างไฟล์ PDF/XLSX ไม่ได้ (Totalizer ส่งออก CSV และพิมพ์ได้แล้ว)
- ข้อมูลเซนเซอร์บนแดชบอร์ดยังใช้ polling มีแค่ alarm ที่ส่งผ่าน WebSocket
- รองรับโรงงานเดียว ยังไม่มีระบบแยกข้อมูลหลายไซต์
